# WebUI 使用说明

充电控制 WebUI 在模块管理器中打开（KernelSU 管理器、MMRL、WebUI-X 等）。界面为 **Vue 3** 单页应用，底部四页：**概览 · 策略 · 日志 · 我的**。

## 打开方式

1. 安装时选择默认安装或自定义安装并勾选 **WebUI**
2. 重启后在模块管理器进入 **充电控制 → WebUI**
3. 需管理器提供 shell 桥接（普通浏览器无法执行模块命令）

若提示「未检测到 WebUI 桥接」，请换用支持模块 WebUI 的客户端。

## 概览

概览页展示实时电池状态与当前策略摘要，适合快速确认「是否在充、为何停充、阈值是否合理」。

| 区域       | 内容                                                           |
| ---------- | -------------------------------------------------------------- |
| 状态 Hero  | 电量、温度、充电状态徽章与说明文案                             |
| 模块总开关 | 关闭后写入软关闭标记，逻辑暂停（等同快捷脚本「关闭充电控制」） |
| 当前策略   | 电量 / 温控停充摘要；点按跳转策略页                            |
| 电池状况   | 健康状态、设计容量、满充容量、SOH 等（因主题包布局略有不同）   |
| 运行详情   | 充电电流、USB 状态、停充原因、首选停充节点、模块版本等         |
| 下拉刷新   | 重新读取 `battery_info.sh` 与模块状态                          |

三套主题包在概览上的信息分区不同：

- **默认**：Hero 电池动画 + 「电池本钱」卡片
- **MD3**：tonal 状态条 + 并排指标 + 「电池健康」+ 运行详情
- **MIUIX**：总览 / 当前策略 / 运行参数 / 独立「电池」段

### 刷新状态

下拉概览页或点刷新会重新执行状态脚本，更新电量、温度、停充原因与简介文案。停充配置修改后一般 **约 3 秒内** 由主循环生效，无需重启。

## 策略

策略页按功能分区：**阈值（何时停）→ 行为 / 电流 → 本机停充开关与实测**。停充与电流控制 **分开保存**。

### 电量停充

| 项              | 说明                                                            |
| --------------- | --------------------------------------------------------------- |
| 停止 / 恢复电量 | 达到停止值停充，降到恢复值再继续；停止填 `110` 表示关闭电量停充 |
| 延时秒数        | 触发停充前的等待时间（1–120 秒）                                |
| 停充时段        | 可选；填写后仅在时段内按电量停充（温控不受限）                  |
| 充满再停        | 到达 100% 后等待涓流结束再停充                                  |

### 停充行为

| 项            | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| 停充持锁      | 关 / 自动 / 开；息屏深睡改回节点时建议开或自动（魅族 / MCA） |
| 自动拔插      | 插电时模拟拔插，有助于激活快充                               |
| 兼容模式      | 与其它快充 / 限流模块同装时建议开启，跳过本模块电流控制      |
| 停充/恢复通知 | 系统通知总开关；可分控停充 / 恢复 / 失败，并设勿扰时段       |

### 温控停充

开启后可设停止温度与恢复温度。电量与温控可能同时触发；模块会记录停充原因，只有电量与温度 **均恢复** 后才继续充电。

### 电流控制（可选）

安装时勾选「电流控制」后才会显示本区块；总开关 **默认关闭**。

| 项                  | 说明                                                                           |
| ------------------- | ------------------------------------------------------------------------------ |
| 旁路                | 可按电量、温度或时段（支持跨天）任一条件触发；方式可选模拟写电流或自动探测节点 |
| 慢充                | 电量达到阈值后改用较小电流                                                     |
| 默认限流 / 温控阶梯 | 一限、二限温度与对应电流                                                       |
| 游戏限流            | 可加载已安装应用列表搜索勾选，或手动编辑包名                                   |
| 进阶                | 重申间隔、漂移、台阶电流与路径等                                               |

字段含义与范围钳位见 [配置说明](/guide/config#电流控制currentjson可选)。

### 停充开关（本机节点）

| 区块           | 说明                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 首选停充开关   | 编辑 `device.profile` 的 preferred / reassert；测开关结果可写入此处  |
| 自定义供电开关 | 自动扫描无效时填写；卡片内只读预览，点按打开编辑器                   |
| 测开关与缓存   | 快速 / 完整测开关（后台执行）；清除 `list_switch` / `device.profile` |

详见 [配置说明](/guide/config#自定义供电开关power_switch)。

### 更多选项

除省电间隔外，这里有两个与曲线相关的开关：

- **显示充放电曲线**：控制概览页是否显示曲线。关闭时会连采样一起停掉，采样开关随之置灰
- **充放电历史采样**：只在充电时采样，用途是给曲线加上**充电电流线**。关掉它曲线依然能画电量与温度线（那部分数据来自系统自带的电池记录），只是没有电流线

所以重新打开曲线显示时，采样不会自动跟着打开——是否需要电流线由你决定。

### 事件唤醒（守护）

守护是一个很小的原生程序（`bin/qscd`），未插电时让模块阻塞在内核充电事件上，而不是每隔几十秒醒一次，能进一步降低待机耗电。它**不写任何充电节点、不做阈值判定**，只负责"等"，所以它出问题最坏也只是退回定时轮询，不会导致停充失效。

| 操作           | 说明                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 启用事件唤醒   | 总开关。没有守护文件时置灰，卡片会说明原因                               |
| Rust 版 / C 版 | 二选一。安装包自带则直接切换，否则从模块官网下载；选另一个会替换掉当前的 |
| 删除守护文件   | 回到纯脚本定时轮询，随时可重新下载                                       |

#### 两版能力已经不同

Rust 版是主力，除基础的事件唤醒外还有两项 C 版没有的能力：

- **按阈值过滤电池事件**：充电中离停充阈值还远时不叫醒脚本，把这段的轮次整段省掉。`loop_interval_plugged_native_sec` 这个设置只对它有效
- **原生进程检测**：按 App 停充与游戏识别里判断「包名有没有在跑」时遍历 `/proc`，替代 `ps` 全量快照；同时只认包名完全相等，不会像子串匹配那样误命中同前缀的包

C 版冻结在基础事件唤醒上，只修 bug、不再跟进新能力。装 C 版一切照常工作，只是用不上上面两项，对应场景自动退回原有做法（定时间隔、`ps` 快照）。卡片顶部会在用 C 版时标注这一点。

下载会先取文件清单，再下载二进制并比对 sha256，然后跑一次本机自检；任何一步不通过都会回滚到原来的文件，不会留下来源不明的可执行文件。卡片中的运行自检还会显示 netlink、电源节点和当前二进制能力；开启 `debug_on` 后可显示最近一次等待结果。切换成功后模块服务会自动重启以生效。

守护只提供 arm64 与 armv7 两种；卡片顶部会显示当前用的是哪套实现、来自安装包还是下载、以及自检是否通过。

## 日志

- 查看 `data/log.log` 尾部（停充、恢复、限流、节点写入等）
- 每行格式：`日期时间 [等级] 内容`，等级为 `INFO` / `WARN` / `ERROR` / `DEBUG`
- 页面按等级着色；筛选项默认「全部」，可只看某一等级
- 可切换「会话」视图，按停充→恢复折叠
- **下拉刷新** / 按钮 **刷新** / **清空**（清空不影响配置）
- 排查异常时可搜索 `stop`、`resume`、`preferred_switch`、`current`

## 与 Action 的分工

| 入口       | 适合做什么                                                                     |
| ---------- | ------------------------------------------------------------------------------ |
| **WebUI**  | 改阈值、开关模块、电流控制、测开关、看日志、调外观与主题、机型分享             |
| **Action** | 一轮音量选择：音量上（或 5 秒未按）刷新状态；音量下插电快速测开关 / 未插电诊断 |

SukiSU 等环境 Action 总时长有限，完整测开关请用 WebUI「策略 → 测开关与缓存」或 adb 运行 `bin/test_switch.sh`。

诊断报告输出：`/sdcard/qsc_diagnose.txt`。

## 常见问题（WebUI）

**状态一直加载失败**  
检查管理器 WebUI 桥接是否正常；对比 Action 刷新输出与 `data/log.log`。

**改了策略但没立刻停充**  
主循环约 3 秒一轮；若已插电且条件仍满足，可能需等待下一轮或下拉刷新查看原因。

**电流控制区块不显示**  
安装时未勾选电流控制组件，或 `current.json` 不存在；重新刷入并选择安装即可。

**MIUIX 深色莫奈背景异常**  
可在「我的 → 显示」关闭莫奈取色，或切换浅色 / MD3 主题包。

更多排障见 [常见问题](/guide/faq)。
